# 요구사항 정의서 — AI 가상 안경 피팅 (웹 클라이언트 + 안드로이드 하이브리드)

| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.0 (2026-09-16) |
| 근거 | 발주사 RFP「안드로이드 및 웹 환경 AI 가상 피팅(안경) 솔루션 개발」 |
| 대상 범위 | 웹 클라이언트 + 안드로이드 WebView 하이브리드 셸. UI/UX 디자인·백엔드·커머스 제외 |
| 관련 문서 | [02 과업 범위·제외 명세](02-과업범위-제외명세.md) · [06 검수 기준서](06-검수기준서.md) · [설계 명세](../superpowers/specs/2026-09-08-virtual-glasses-fitting-poc-design.md) |

RFP 본문의 서술형 요구를 **검증 가능한 단위**로 분해한 문서다. 각 요구사항은 [06 검수 기준서](06-검수기준서.md)의 측정 항목과 1:1로 대응하며, 대응되지 않는 요구사항은 두지 않는다.

상태 표기: **확보** = PoC에서 구현·측정 완료 / **부분** = 구현되었으나 본 개발에서 제품화 필요 / **미착수** = 본 개발 신규

---

## 1. 기능 요구사항 (FR)

### 1.1 얼굴 추적 및 정합 — RFP 2-1

| ID | 요구사항 | 수용 기준 | 상태 |
|---|---|---|---|
| FR-01 | 실시간 얼굴 추적 및 랜드마크 검출 | MediaPipe Face Landmarker로 478점(468 + 홍채 10) · 4×4 얼굴 변환 행렬 · 블렌드셰이프 52종을 매 프레임 산출 | 확보 |
| FR-02 | 얼굴 크기에 따른 자동 스케일링 | 관자놀이 폭(127↔356) 60 % + 눈 외각 폭(33↔263) 40 % 가중 비율로 폭 스케일 산출, 0.8~1.25 클램프. PD 확보 시 홍채 mm 기준 실치수 모드 | 확보 |
| FR-03 | 얼굴 각도에 따른 자동 회전 | 얼굴 변환 행렬을 안경 노드에 직접 적용. yaw ±45°, pitch ±30°, roll ±30° 범위에서 추종 | 확보 |
| FR-04 | 자연스러운 착지 높이·깊이 | 코 패드 접촉점을 코 옆면 삼각형 높이장에 얹어 원점 깊이 결정. 패드 정보 부재 시 능선 폴백 | 확보 |
| FR-05 | 얼굴 관통 방지 | 림 외곽선·브릿지 바·코 패드 프로브를 눈썹·볼·코 높이장과 비교해 전방 보정, 다리는 측두부 정점 띠 기준으로 벌림(0~15°) | 확보 |
| FR-06 | 오클루전 | 478점 깊이 전용 얼굴 메시 + 두개골·귀 프록시 메시를 먼저 렌더해 가려질 부분을 가림 | 확보 |
| FR-07 | 추적 상태 관리 | Tracking / Degraded / Lost 상태기계. Lost 시 마지막 포즈 12프레임 유지 후 300 ms 페이드, 재획득 3프레임 히스테리시스 | 확보 |
| FR-08 | 시간 필터링 | 행렬을 이동·쿼터니언·스케일로 분해해 One-Euro 필터 적용. Degraded 시 필터 강도 2배 | 확보 |
| FR-09 | 팬토스코픽 틸트 | 프런트 8° 틸트, 다리는 힌지에서 역회전으로 수평 유지 | 확보 |

| FR-14 | 카드 기준 캘리브레이션 | ISO ID-1 카드(85.60 × 53.98 mm) 긴 변 기준으로 개인 홍채 지름 보정 | 부분 — PoC는 수동 드래그, 본 개발에서 자동 검출 |

## 2. 비기능 요구사항 (NFR)

| ID | 항목 | 기준 | 근거 |
|---|---|---|---|
| NFR-01 | 정합 정확도 | 브릿지 착지 오차 ≤ 2 mm, 프레임 폭 비율 오차 ≤ 3 % | RFP 2-1 "자동 스케일링/회전" |
| NFR-02 | 착용 자연스러움 | 렌즈 뒷면–각막 정점간 거리 10~23 mm, 보정 후 관통 잔여 ≤ 0 mm | 실착용 대비 부유·관통 방지 |
| NFR-03 | 정지 안정성 | 정지 3초 지터 ≤ 0.5 px(720p 환산) / ≤ 0.3° | RFP 2-1 "안정적 렌더링" |
| NFR-04 | 모션 지연 | raw 대비 filtered yaw 상호상관 지연 ≤ 50 ms | 〃 |
| NFR-05 | 추적 유지율 | yaw ±45° 스윕 중 Tracking 비율 ≥ 95 %, 재획득 ≤ 300 ms | 〃 |
| NFR-06 | 렌더 성능 | 중급 안드로이드 ≥ 24 fps, 데스크톱 ≥ 30 fps, 캡처→렌더 파이프라인 ≤ 80 ms | RFP 2-1 "실시간" |
| NFR-07 | 조명 내성 | 300 lx / 50 lx / 역광 3조건에서 NFR-05 충족 | RFP 2-1 "다양한 조명 환경" |
| NFR-08 | PD 정확도 | MAE ≤ 2.0 mm, 95 % 일치 범위 ±3 mm, 반복 표준편차 ≤ 1.0 mm, 측정 성공률 ≥ 90 % | RFP 2-3 "±수 mm 참고 수준" |
| NFR-09 | 개인정보 | 얼굴 영상·랜드마크는 기기를 벗어나지 않음. 서버 전송은 동의 시 수치만 | RFP 없음 — 필수 설계 제약 |
| NFR-10 | 의료기기 비해당 | 진단·검안·조제 용도가 아님을 UI에 상시 고지 | RFP 2-3 명시 |
| NFR-11 | 브라우저 호환 | [04 지원 매트릭스](04-지원브라우저-디바이스매트릭스.md) 기준 충족 | RFP 2-2 |
| NFR-12 | 전송 보안 | HTTPS 필수(카메라 권한 전제). 혼합 콘텐츠 없음 | 브라우저 제약 |
| NFR-13 | 유지보수성 | 공용 코어와 플랫폼 계층 분리, 회귀 테스트 및 골든 벡터 상시 통과 | RFP 우대사항 "공용 코어 설계" |
