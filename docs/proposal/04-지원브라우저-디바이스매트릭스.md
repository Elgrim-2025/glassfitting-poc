## 1. 지원 하한은 어디서 나오는가

임의로 정한 값이 아니라 **제품이 반드시 써야 하는 웹 기능**에서 역산했다.

| 필요 기능 | 용도 | 최초 지원 |
|---|---|---|
| `getUserMedia` (보안 컨텍스트) | 카메라 입력 | Chrome 53 · Safari 11 |
| WebGL2 | 3D 렌더 · MediaPipe GPU delegate | Chrome 56 · Safari 15 (iOS 15) |
| **WebAssembly SIMD** | 추론 성능 — 없으면 FPS 절반 이하 | **Chrome 91 · Safari 16.4 (iOS 16.4)** |
| `requestVideoFrameCallback` | 프레임 동기화 (없으면 `requestAnimationFrame` 폴백) | Chrome 83 · Safari 15.4 |

**결정 요인은 WebAssembly SIMD다.** 이것이 지원 하한을 Chrome 91 / Safari 16.4로 밀어 올린다.

## 2. 지원 등급

| 등급 | 의미 |
|---|---|
| **A — 보증** | 검수 대상. [06 검수 기준서](06-검수기준서.md)의 모든 수치 기준을 충족해야 함 |
| **B — 동작** | 기능은 동작하나 성능 기준은 보증하지 않음. 버그 리포트는 접수하되 수정은 협의 |
| **C — 미지원** | 기능 차단 + 안내 화면 노출 |

### 2.1 모바일

| 플랫폼 | 브라우저 | 최소 버전 | 등급 | 비고 |
|---|---|---|---|---|
| Android | Chrome | 94+ | **A** | 기준 플랫폼 |
| Android | Samsung Internet | 17+ | **A** | Chromium 기반, 국내 점유율 고려 |
| Android | **본 하이브리드 앱** | System WebView 94+ | **A** | OS 하한 Android 10 (API 29) |
| Android | Firefox | 최신 | B | 동작하나 GPU delegate 경로 성능 미보증 |
| iOS | Safari | **iOS 17+** | **A** | 기술적 하한은 16.4, 여유를 두어 17로 설정 |
| iOS | Chrome · Edge · 기타 | iOS 17+ | **A** | iOS에서는 전부 WebKit 엔진 → Safari와 동일 |

### 2.2 데스크톱

| OS | 브라우저 | 최소 버전 | 등급 |
|---|---|---|---|
| Windows · macOS | Chrome | 94+ | **A** |
| Windows | Edge | 94+ | **A** |
| macOS | Safari | 16.4+ | **A** |
| Windows · macOS | Firefox | 최신 | B |
| 전체 | Internet Explorer | — | **C** — WebGL2·WASM 미지원, 기술적으로 불가능 |

### 2.3 인앱 브라우저 — 별도 취급 필요

**국내 커머스에서 가장 흔한 유입 경로이면서, 카메라가 가장 자주 막히는 환경이다.**

| 환경 | 상태 | 대응 |
|---|---|---|
| 카카오톡 인앱 브라우저 (Android) | 조건부 동작 | 실측 필요 |
| 카카오톡 인앱 브라우저 (iOS) | **카메라 차단 사례 다수** | "Safari에서 열기" 안내 화면 |
| 네이버 앱 인앱 브라우저 | 조건부 동작 | 실측 필요 |
| 인스타그램 · 페이스북 인앱 | **카메라 차단 사례 다수** | 외부 브라우저 유도 |

대응 방식: 진입 시 `getUserMedia` 가용성을 검사하고, 실패하면 **"외부 브라우저에서 열기" 안내 화면**으로 전환한다. 인앱 브라우저는 버전 고지 없이 동작이 바뀌므로 **개별 인앱 환경은 A등급에 넣지 않는다.**

> ※ 미팅 확인: 발주사 서비스의 실제 유입 경로에서 인앱 브라우저 비중이 어느 정도인지. 비중이 높다면 안내 화면 설계를 UI 범위에 포함해야 한다.

## 3. 기준 해상도

### 3.1 화면 (렌더 레이아웃)

| 구분 | 기준 해상도 | 대응 범위 |
|---|---|---|
| PC Web | **1280 × 720** | 1024 × 768 ~ 1920 × 1080 |
| Mobile Web · App | **390 × 844** (세로) | 360 × 640 ~ 430 × 932 |
| Tablet | **768 × 1024** | 768 × 1024 ~ 1024 × 1366 |
| 가로 모드 | 지원 (레이아웃 재배치) | 카메라 종횡비 전환 포함 |

### 3.2 카메라 입력 (성능 프로파일)

화면 해상도와 별개로, **추론에 넣는 영상 해상도**가 성능을 지배한다. 기기 벤치마크 결과로 자동 선택한다.

| 프로파일 | 입력 해상도 | 블렌드셰이프 | 적용 대상 |
|---|---|---|---|
| High | 1280 × 720 | 사용 | 데스크톱, 고성능 모바일 |
| **Standard (기준)** | **1280 × 720** | 사용 | 중급 안드로이드 — 검수 기준 플랫폼 |
| Low | 640 × 480 | 미사용 | 저사양 기기 |
| Fallback | 640 × 480 + 프레임 스킵·보간 | 미사용 | Low에서도 24 fps 미달 시 |

> 입력 해상도를 640 × 480으로 낮추면 **PD 측정 정확도가 함께 떨어진다.** 50 cm 거리에서 홍채 지름이 게이팅 하한(12 px)에 근접하기 때문이다. Low 프로파일에서는 PD 측정 시 "화면에 얼굴을 더 가까이" 안내를 띄운다.

## 4. 검수 대상 기기

| 구분 | 기기 | 상태 |
|---|---|---|
| 중급 안드로이드 (기준) | ※ 미확정 | **발주사 확인 필요** |
| 고급 안드로이드 | ※ 미확정 | 〃 |
| iOS | iPhone (iOS 17+) 1대 | 당사 보유 |
| 데스크톱 | macOS + Chrome / Safari | 당사 보유 |

> ※ 미팅 확인: 검수 기준이 될 **중급 안드로이드 모델명**을 발주사가 지정해 주어야 한다. NFR-06(≥ 24 fps)의 판정 대상이 이 기기다. 기기 대여가 어려우면 모델명만 확정하고 당사가 동급 기기를 조달한다.

## 5. 차단 조건과 안내

아래 상황에서는 피팅을 시작하지 않고 안내 화면으로 전환한다. **안내 화면의 디자인은 발주사 UI 범위**이며, 당사는 상태와 사유 코드를 이벤트로 노출한다.

| 사유 코드 | 조건 | 안내 |
|---|---|---|
| `INSECURE_CONTEXT` | HTTPS 아님 | 보안 연결 필요 |
| `NO_GETUSERMEDIA` | 카메라 API 없음 (인앱 브라우저 등) | 외부 브라우저에서 열기 |
| `NO_WEBGL2` | WebGL2 미지원 | 브라우저 업데이트 필요 |
| `NO_WASM_SIMD` | SIMD 미지원 | 〃 |
| `PERMISSION_DENIED` | 사용자가 카메라 거부 | 권한 설정 안내 |
| `BROWSER_TOO_OLD` | §2 최소 버전 미만 | 브라우저 업데이트 필요 |
