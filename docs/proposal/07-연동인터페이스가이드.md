# 연동 인터페이스 가이드 — 발주사 개발자용

| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.0 (2026-09-16) |
| 대응 | RFP 과업 2-4「제품 데이터와 연결 가능한 표준 API 인터페이스 설계 및 제공」 |
| 정식 규격 | **[`docs/api/openapi.yaml`](../api/openapi.yaml)** (OpenAPI 3.1) — 필드 정의의 단일 출처 |
| 에셋 규격 | **[`docs/assets/glb-spec.md`](../assets/glb-spec.md)** |

본 문서는 규격을 다시 적지 않는다. **발주사 서버 개발자가 무엇을 구현하면 되는지**를 순서대로 안내하는 가이드이며, 필드 세부는 위 두 문서를 본다.

---

## 1. 한 장 요약

발주사는 **읽기 전용 엔드포인트 3개**를 구현하면 된다. 그러면 피팅 클라이언트가 코드 수정 없이 붙는다.

| # | 엔드포인트 | 필수 | 용도 |
|---|---|---|---|
| 1 | `GET /v1/frames` | 필수 | 프레임 목록 (페이징 · 증분 동기화) |
| 2 | `GET /v1/frames/{frame_id}` | 필수 | 프레임 상세 (스펙 + 에셋 + 앵커) |
| 3 | `GET /v1/frames/{frame_id}/assets/{variant}` | 필수 | GLB · 썸네일 바이너리 |
| 4 | `POST /v1/fit-sessions` | **선택** | PD·착용 결과 로그 (동의 시 수치만) |

클라이언트는 `src/platform/product/adapter.ts` 하나로 이 API를 소비한다. PoC 단계에서는 `public/api/v1/*.json` 정적 파일이 같은 형태로 응답하므로, **발주사 서버가 준비되기 전에도 개발이 진행된다.**

---

## 2. 구현 순서

### 2-1. 프레임 상세 응답부터 만든다

가장 중요한 응답이다. 실제 mock 응답:

```json
{
  "frame_id": "FR-0001",
  "name": "블랙 스퀘어 아세테이트 (웰링턴)",
  "spec": {
    "lens_width_mm": 52,
    "bridge_mm": 21,
    "temple_mm": 145,
    "lens_height_mm": 41,
    "frame_width_mm": 148,
    "nose_pad": "fixed"
  },
  "assets": {
    "glb_url": "/assets/frames/FR-0001.glb",
    "thumbnail_url": "/assets/frames/FR-0001.svg",
    "anchor": {
      "bridge": [0, 0, 0],
      "temple_left": [-72.2, 14, 6],
      "temple_right": [72.2, 14, 6],
      "nose_pad_offset": [9.5, -4, 0],
      "lens_plane_mm": 6,
      "lens_back_mm": 6.33,
      "rim_depth_mm": 4.5,
      "rim_width_mm": 5.2,
      "rim_back_mm": 2.5,
      "rim_outline_mm": [[67.56, 13.92], [66.71, 17.93], "… 48점"]
    }
  },
  "fit_hints": { "recommended_pd_range_mm": [58, 70] },
  "version": 3,
  "updated_at": "2026-09-08T00:00:00Z"
}
```

| 블록 | 누가 채우나 | 없으면 |
|---|---|---|
| `spec` | **발주사 상품 DB** — 안경테 표준 각인값(52□21-145) 그대로 | 필수. 없으면 서비스 불가 |
| `assets.glb_url`, `thumbnail_url` | 발주사 | 필수 |
| `assets.anchor` | **3D 에셋 제작 시 함께 산출** | `bridge`/`temple_*`/`nose_pad_offset`은 필수. 나머지는 기본값으로 대체되나 **정합 품질이 떨어진다** |
| `fit_hints` | 선택 | 없어도 동작 |
| `version`, `updated_at` | 발주사 | 캐시 무효화에 사용 |

> **`anchor`는 상품 담당자가 손으로 채울 값이 아니다.** 3D 에셋 제작 파이프라인에서 자동 산출되어야 한다. 당사가 제공하는 검수 스크립트가 GLB에서 이 값을 추출·검증한다.

### 2-2. 목록 응답

```
GET /v1/frames?page=1&size=50&updated_after=2026-09-01T00:00:00Z
```

```json
{ "items": [ /* 상세와 동일한 Frame 객체 배열 */ ], "page": 1, "size": 50, "total": 132 }
```

`updated_after`는 **증분 동기화용**이다. 프레임 수가 많아지면 클라이언트가 전체를 매번 받지 않도록 이 파라미터를 반드시 지원해야 한다.

### 2-3. 에셋 바이너리

```
GET /v1/frames/FR-0001/assets/glb        → Content-Type: model/gltf-binary
GET /v1/frames/FR-0001/assets/thumbnail  → image/png 또는 image/svg+xml
```

**캐시 헤더가 필수다.** GLB는 프레임당 0.5~2 MB이고 모바일 데이터로 내려간다.

| 헤더 | 값 |
|---|---|
| `ETag` | 에셋 해시 |
| `Cache-Control` | `public, max-age=86400` 이상 |
| `Content-Type` | `model/gltf-binary` |

### 2-4. 결과 로그 (선택)

```json
POST /v1/fit-sessions
{ "frame_id": "FR-0001", "pd_far": 63.4, "pd_near": 61.2,
  "pd_mono_left": 31.8, "pd_mono_right": 31.6,
  "confidence": 0.87, "sample_count": 42, "device": "Android/Chrome", "consent": true }
```

**전송되는 것은 수치뿐이다.** 얼굴 영상·랜드마크·이미지는 어떤 경우에도 서버로 가지 않는다. `consent: true`가 없으면 클라이언트가 이 요청 자체를 보내지 않는다.

## 3. 3D 에셋 규격 요점

전문은 [`glb-spec.md`](../assets/glb-spec.md). 발주사 에셋 제작자가 가장 자주 틀리는 세 가지만 옮긴다.

| 항목 | 규격 | 틀리면 |
|---|---|---|
| **원점** | **코 패드 접촉면 중심** (렌즈 평면이 아니다) | 안경이 얼굴 앞에 뜨거나 파고든다 |
| **축** | +Y 위, **+Z 얼굴 정면**, 다리는 −Z로 뻗음 | 안경이 뒤집히거나 옆을 본다 |
| **단위** | 1 glTF 단위 = 1 mm. 루트 노드에 스케일 금지 | 크기가 1000배로 어긋난다 |

| 제한 | 값 |
|---|---|
| 삼각형 | ≤ 50,000 (샘플 ≈ 25,000) |
| 텍스처 | ≤ 2048², 4장 이하 |
| 용량 | ≤ 2 MB 권장 (샘플 ≈ 0.5 MB) |
| 스펙 대비 실측 오차 | ≤ 1 mm (당사 검수 스크립트가 자동 판정) |
| 필수 노드 | `lens_L/R`, `temple_L/R`, `anchor_bridge`, `anchor_temple_L/R` |

`L`/`R`은 **모델 공간 −X/+X** 라벨이며 착용자 좌우와 반대다. 노드 이름에 착용자 기준을 쓰지 않는다.

## 4. 오류 처리 규약

| 상황 | 서버 응답 | 클라이언트 동작 |
|---|---|---|
| 프레임 없음 | `404` | 목록으로 복귀, 사유 이벤트 발행 |
| 서버 오류 | `5xx` | 지수 백오프 3회 재시도 후 사유 이벤트 |
| GLB 로드 실패 | 임의 | **`spec` 기반 절차적 프레임으로 폴백** — 피팅은 계속됨 |
| 스펙 필드 누락 | 임의 | 해당 프레임을 목록에서 제외하고 경고 로그 |

**GLB 폴백이 있으므로 에셋 준비가 늦어도 개발과 검수는 진행된다.** 다만 외관 평가는 실제 GLB가 있어야 한다([05 일정](05-일정-마일스톤.md) P-2).

## 5. 발주사 확인 필요

| 항목 | 내용 |
|---|---|
| 인증 | 제품 마스터 API에 인증이 필요한가. 필요하면 방식(API Key / OAuth)과 클라이언트 보관 정책 — **공개 웹 클라이언트이므로 비밀키를 넣을 수 없다** |
| CORS | 피팅 클라이언트 도메인을 허용 목록에 넣어야 한다. 도메인 확정 필요 |
| 베이스 URL | 개발·스테이징·운영 환경별 URL |
| 에셋 호스팅 | API 서버 직접 서빙인가, CDN인가 |
| `fit-sessions` | 구현 여부. 미구현이면 클라이언트에서 기능 비활성 |
| 프레임 수 | 서비스 예정 프레임 종수 (페이징·캐시 전략에 영향) |
